Context

See proposal.md, Why. The Rust extension is RustExtension in crates/morphir-rust-binding. It has the frontend and backend roles, and export_extension!(RustExtension, frontend, backend) makes it an Extism WASM guest (extism-kernel-v1). morphir-extension-sdk 0.4.0, in this workspace, already does the MEP 0.2.0-draft.1 work for a guest that opts in:

  • A guest opts in with ExtensionCapabilities::model_transport and implements Frontend::compile_model and Backend::generate_model. The trait defaults refuse.
  • The guest protocol session adds 0.2.0-draft.1 to the describe claims when the support is valid, selects it at initialize only when the host sends a model transport offer, intersects the complete tuples in the host's order and takes the smaller limits.
  • Before dispatch, it refuses a rich request whose tuple was not agreed, whose envelope does not match the tuple or whose payload fails its length or SHA-256 check. After the call, it checks a successful compile result's model.
  • The Ion reader is native only. On wasm32, a guest that advertises an Ion tuple is invalid.

The reference is finos/morphir-gleam rust/crates/morphir-gleam-binding/src/model_transport.rs (release extension/gleam/v0.4.0). The MoonBit CLI host offers morphir-model / ion-binary, then morphir-ir / morphir-json, both at IR 4.0.0, and uses the first tuple that the extension agrees on.

Goals and non-goals

Goals: the requirements in specs/rust-extension-model-operations/spec.md, through the SDK's existing opt-in, with no SDK change; MEP 0.1 behaviour unchanged; a released bundle that the MoonBit worker host runs on both lines.

Non-goals: Ion transport; IR v3 model tuples; multi-document compilation or compile dependencies (the frontend still compiles one document and refuses dependencies); release attestations, which this repository's extension release does not make today; the finos/morphir bundle pins.

Decisions

MEP-1. Use the SDK opt-in, not a second protocol layer

RustExtension::capabilities() sets model_transport, and the Frontend and Backend impls forward compile_model and generate_model to a new private module model_transport. The SDK session then gives negotiation, the 0.1 fallback and the admission checks to both the native NativeExtension dispatch and the WASM guest. The alternative, a guest-specific protocol layer like the Gleam core-Wasm guest, would duplicate the session for no gain: the Extism route already reaches the MoonBit worker host.

MEP-2. One JSON tuple per operation, at IR 4.0.0

{"operation": "morphir.frontend.compileModel", "profile": "morphir-ir", "codec": "morphir-json",
 "envelopeVersion": "0.1.0-draft.1", "irVersion": "4.0.0"}

and the same tuple for morphir.backend.generateModel. No Ion tuple: the release artifact is a WASM guest, and the SDK refuses Ion support on wasm32 rather than transcode (morphir-opua.1.3.1.3 tracks a WASM Ion reader). A native-only Ion tuple would make the native and WASM claims differ, and the packager reads the claims from the WASM. No IR 3 tuple: the hosts offer only IR 4.0.0, and IR 3 stays available on the 0.1 line.

MEP-3. The payload is the legacy IR v4 document

compileModel runs the existing compile with irVersion 4 and encodes the returned IR v4 JSON with ModelPayload::from_bytes. modelId is the package name and revision is sha256: and the payload digest, as in the Gleam extension. generateModel decodes the payload through the SDK's retain_model with the extension's own tuple and limits, then runs the existing generate. So the two lines give the same IR and the same Rust, and the golden tests compare both lines with one recorded output.

MEP-4. Refusals

The SDK session refuses an unagreed tuple, a wrong envelope and a failed integrity check before the extension runs. The module checks the tuple again, because the native trait methods can be called without a session, and refuses with InvalidParams. A required guarantee gives a failed GenerateResult with diagnostic RS_UNSUPPORTED_GUARANTEE; the session already refuses it first. A frontend failure is CompileModelResult::Failed with the frontend's diagnostics.

MEP-5. Limits

The guest advertises 64 MiB encoded, 48 MiB decoded, depth 128 and 16 Mi nodes. Hosts take the smaller value of each limit (the MoonBit host offers 2 MiB decoded), so these are upper bounds only. The host's WASM memory and instruction budgets still apply. Depth 128 is the deepest document that serde_json decodes with its default recursion limit, counted as admission counts depth, so every payload that the session admits can be decoded. The Gleam extension's depth 1024 was not taken: a host that agreed a depth above 128 could admit a payload that the decoder then refuses. Disabling the recursion limit was not chosen either, because a deep document could then overflow the WASM guest's stack.

REL-1. Release 0.4.0 with the existing workflow

.github/extensions.toml sets mep_versions = ["0.1", "0.2.0-draft.1"]; the packager already compares it with the claims that it reads from the exact WASM, and the claims carry modelTransport. The binding version moves to 0.4.0 (a new minor: a new protocol line). The tag extension/rust/v0.4.0 on the merge commit starts the existing release workflow, which publishes the WASM, .wasm.sha256 and release.json. The dry run is the same resolution, build and asset validation, run locally on the merged commit before the tag.

Risks and trade-offs

RiskMitigation
An older host reads 0.2.0-draft.1 or modelTransport in the descriptor claims and refuses the bundle.Run the existing 0.1-only paths: the installed-bundle test of morphir-host-native and mise run test:cli-release rust with the pinned finos/morphir CLI.
A host compares the claims of initialize (narrowed tuples and limits) with the describe claims and finds a difference.Qualify on the MoonBit worker host, native and npm, before release. A difference that the SDK causes is fixed in a separate SDK pull request first.
A model larger than the host's WASM budgets fails where the legacy line passes.The payload is the same document as the legacy result; the budgets are the host's, not the transport's.

Migration plan

Additive. Hosts that offer only MEP 0.1 see no change. To roll back, publish nothing more and keep the v0.3.0 pins; a released tag is not moved or deleted.
